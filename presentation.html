# 1. Initialize Feature Store from snowflake.ml.feature_store import FeatureStore, CreationMode fs = FeatureStore(session, database, schema, default_warehouse=warehouse, creation_mode=CreationMode.CREATE_IF_NOT_EXIST) # 2. Register PATIENT entity entity = Entity("PATIENT", join_keys=["PATIENT_ID"]) fs.register_entity(entity) # 3. Build features server-side (Snowpark pushdown) feature_df = df.with_column("SHOCK_INDEX", F.col("HEART_RATE") / F.col("SYSTOLIC_BP") ).with_column("PULSE_PRESSURE", F.col("SYSTOLIC_BP") - F.col("DIASTOLIC_BP")) # 4. Register Feature View (auto-refreshes every 1 min) fv = FeatureView("PATIENT_FEATURES", [entity], feature_df, refresh_freq="1 minute") fs.register_feature_view(fv, version="v1", block=True) # 5. Point-in-time retrieval → persisted train/test tables training_df = fs.retrieve_feature_values( spine_df=spine.sample(frac=0.8), features=[fv]) training_df.write.save_as_table("TRAINING_FEATURES")

Key Code — dag.py
-- Wrap each step in a Python Stored Procedure CREATE OR REPLACE PROCEDURE RUN_FEATURE_ENGINEERING() RETURNS VARIANT LANGUAGE PYTHON RUNTIME_VERSION = '3.11' PACKAGES = ('snowflake-ml-python', 'scikit-learn') IMPORTS = ('@JOB_PAYLOADS/source.zip') EXECUTE AS CALLER AS $$ def handler(session): from source.pipeline.step1_feature_engineering import run return run(get_config(), session) $$; -- Root task: CRON weekly schedule CREATE OR REPLACE TASK PIPELINE_ROOT_TASK WAREHOUSE = ML_DEMO_WH SCHEDULE = 'USING CRON 0 2 * * 0 America/Los_Angeles' ALLOW_OVERLAPPING_EXECUTION = FALSE AS CALL RUN_FEATURE_ENGINEERING(); -- Child tasks chained with AFTER CREATE OR REPLACE TASK PIPELINE_TRAIN_TASK AFTER PIPELINE_ROOT_TASK AS CALL RUN_TRAIN_EVALUATE(); ALTER TASK PIPELINE_ROOT_TASK RESUME; -- Manual trigger: EXECUTE TASK PIPELINE_ROOT_TASK; -- CLI: python -m source.pipeline.dag --run
Failure Behavior

If TRAIN TASK fails the promotion gate, DEPLOY and MONITOR tasks are skipped. The live service continues on the last approved version — no downtime, no bad model in production.

Task Observability

All run history, durations, and errors visible in Snowsight → Data → Tasks. Configure Snowflake Alerts with Slack/email webhooks on task failure.

CLI Management
# Rebuild from scratch python -m source.pipeline.dag --teardown python -m source.pipeline.dag # Trigger immediately python -m source.pipeline.dag --run

Summary

Key Takeaways

Everything you saw today runs inside a single Snowflake account

1
Zero Data Movement. Training data, feature computation, model training, HPO, serving, and monitoring all run inside Snowflake. Patient data never left the security boundary.
2
Feature Store Eliminates Skew. SHOCK_INDEX and the other biomarker features are defined once. Identical logic at training and inference time — zero skew possible.
3
Automated HPO via Ray Tune. 30 trials on SPCS with ASHA pruning. Best config written to HPO_RESULTS — read automatically by the training step. No manual wiring needed.
4
Distributed Training at Scale. target_instances=3 is the only change for 3-node distributed training. Same API from 1 to 10+ nodes.
5
Quality Gate + Automated Retraining. Model must pass accuracy ≥ 80% and F1 ≥ 75%. One EXECUTE TASK triggers the full pipeline. Runs weekly on CRON automatically.
